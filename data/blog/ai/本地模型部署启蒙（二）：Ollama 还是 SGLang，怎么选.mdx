选模型运行时不像挑手机，没有「最好」，只有「最合场景」。

我先在本地用 Ollama 跑通了 RAG，后来又上了 SGLang 做高并发服务，才看清两者根本不是一类东西。

先给结论：Ollama 适合「我本地就要跑起来」，SGLang 适合「我要给一堆人稳稳地服务」。

### Ollama 是什么

它就是个开箱即用的本地推理运行时。

一条 `ollama pull`，模型（GGUF 格式）下载好；一条 `ollama run`，直接开聊。

前面还挡着个兼容 OpenAI 的 `/v1` 接口（默认 11434 端口），你原来的 GPT 调用代码把地址指过来就能用。

它对 CPU 友好，普通办公机甚至树莓派都能跑——靠的是量化把模型压小。

单模型、单节点、上手快，是它最大的优点，也划出了它的边界。

### SGLang 是什么

它定位是「生产级推理服务框架」，不是玩具。

模型吃的是 HuggingFace 格式（config.json + safetensors），跟 Ollama 的 GGUF 不是一套，不能直接互换。

它天生为多 GPU 设计：张量并行（TP）把大模型拆到几张卡上一起算。

连续批处理（continuous batching）让一堆请求挤在一块儿跑，吞吐远高于 Ollama 那种「一次招呼一个」的节奏。

还有个拿手好戏：结构化输出，用代码拼复杂 prompt，做 Agent、做批量抽取都很顺手。

代价是门槛高——你得有卡、会配环境、懂点并行。

### 一张表看清

| 维度     | Ollama               | SGLang                      |
| -------- | -------------------- | --------------------------- |
| 定位     | 本地/开发，开箱即用  | 生产服务，高并发            |
| 模型格式 | GGUF（量化友好）     | HuggingFace safetensors     |
| 硬件     | CPU 也能跑           | 多 GPU 才发挥               |
| 并发     | 弱，单流为主         | 强，连续批处理              |
| 上手     | 一条命令             | 要配环境/并行               |
| 典型场景 | 本地 RAG、离线、试玩 | 线上服务、MoE 大模型、Agent |

### 为什么不能混着用

最关键的一点：模型格式不通用。

Ollama 的 GGUF 是量化后打包好的单文件；SGLang 要的是 HuggingFace 那套分片权重。

同一个模型，两边得各自准备一份，没法直接搬。

这也是为什么我上海那台离线服务器用 Ollama（断网、CPU、GGUF 一把带走），而 `Qwen3.6-35B-A3B` 这种 MoE 大模型要上 SGLang 多卡服务。

### 一句话怎么选

只想本地跑通、试想法、做离线 RAG：选 Ollama。

要给很多人用、上 GPU、跑大模型高并发：选 SGLang。

### 下篇预告

对比完，下篇往深里走：为什么大模型非得上显卡、MoE 是怎么回事、SGLang 怎么把 `Qwen3.6-35B-A3B` 这种 35B 总参却只激活 3B 的模型，用 5 张卡跑起来。

还是那句：边做边学，错漏难免，权当笔记。
