前两篇，我们在 CPU 上用 Ollama 跑起了 8B，又用三节点 HA 把它稳住。

但 8B 在 CPU 上到底慢，也干不了太大的活。

要上量，得请显卡。

### 为什么是大模型非得上 GPU

神经网络干的事，说穿了就是海量的矩阵乘法。

CPU 也能算矩阵，但它是为「什么都能干、单线程够快」设计的，核心少。

GPU 反过来了：成千上万个核心，单个不快，但一起算矩阵乘法快得离谱。

大模型那几十亿参数，全靠这种大规模并行才能实时吐字。

所以用 CPU 跑大模型是「能跑」，用 GPU 跑才是「能用好」。

### 引子：一台 5 卡机器

我有个项目叫 SGLangRun，在一台插了 5 张 Tesla T4 的服务器上，用 SGLang 服务一个 35B 的模型。

光看数字会困惑：35B，5 张 T4（每张 16G 显存），怎么塞得下、跑得动？

答案要先从 MoE 讲起。

### MoE：模型里的「专家会诊」

普通（稠密）模型，每个 token 都要过一遍全部参数。

MoE（Mixture of Experts，混合专家）不一样。

它把模型拆成很多个「专家」子网络，再配一个「路由器」。

每个 token 进来，路由器只挑其中少数几个专家来算，其余闲置。

Qwen3.6-35B-A3B 这名字里，A3B 就是 Activated 3B——350 亿总参数，但每个 token 只激活约 30 亿。

好处很妙：知识容量是 35B 的（装得多、懂得广），推理成本却是 3B 的（算得少、跑得快）。

所以它才有资格塞进 5 张 T4。

代价也有：路由不均时有的专家忙死有的闲死；而且全部 35B 权重仍要躺在显存里，只是算的时候少算。

所以「显存放得下」依旧是硬门槛——这就引出下面两招。

### FP8：把模型体积砍半

权重用什么精度存，直接决定占多少显存。

同一个模型，bf16（半精度）版本是 71G，FP8（8 位浮点）版本是 35G，差不多一半。

SGLangRun 的脚本默认就用 FP8——5 张 T4 上每卡才约 7G，余量很足。

FP8 主要省的是显存和带宽；算力的加速要看显卡世代，新卡（H 系列等）才原生吃 FP8，老卡更多是「存得下、算时再抬精度」。

但光「装得下」这一点，就已经决定了能不能跑。

### TP：一张卡放不下，就切到多张

就算 FP8 砍半，35G 也不是一张 T4（16G）能独吞的。

那就把模型切成几片，分到多张卡上协同算一次前向——这叫 Tensor Parallel（张量并行）。

脚本里 `TP_SIZE=5`，正好对应那 5 张卡，各扛一片，步调一致地算。

这也是为什么是「5×T4」而不是「1×大卡」：摊开来，谁都轻松。

### SGLang 和 Ollama 怎么选

讲到这，两套体系就摆清楚了。

Ollama：简单、吃 GGUF、CPU 友好、单机够用，适合「先在本地跑起来」。

SGLang：高性能推理服务引擎，吃 HuggingFace 格式（config.json + safetensors，不认 GGUF），要 GPU、做张量并行、扛高并发，适合「认真服务一个大模型」。

一个坑得提：SGLang 和 Ollama 的模型格式不互通，Ollama 的 GGUF 它不认。

两套各管一段，按需取用。

启动长这样（精简）：

```bash
docker run --rm --gpus all --ipc=host --shm-size=16g \
  -v "$MODEL_PATH:/model:ro" \
  lmsysorg/sglang:latest \
  --model-path /model \
  --served-model-name qwen3.6-35b \
  --tp-size 5 --context-length 65536 \
  --max-num-seqs 3 --host 0.0.0.0 --port 30000
```

端口 30000，上下文 64K，并发 3；`--gpus all` 把卡交给容器；模型挂只读。

它还顺手处理了 Qwen3 的思考模式（`<think>` 标签）解析，以及用一堆离线环境变量把网络彻底掐断——又是断网的套路。

### 让 Docker 看见 GPU 的那块拼图

最后一个容易踩的坑：宿主机装了 NVIDIA 驱动（我这的是 570），只代表本机能用 GPU。

容器是隔离环境，默认看不见 GPU。

要让 `docker run --gpus all` 不报错，还得单独装 nvidia-container-toolkit。

它干的事，是把 GPU 透传进容器。

验证就一条：`docker info` 的 Runtimes 里出现 `nvidia`，就成了。

而且这玩意儿也能离线装（4 个 .deb 打成的包），跟前面 U 盘带 docker、带镜像的思路一脉相承。
