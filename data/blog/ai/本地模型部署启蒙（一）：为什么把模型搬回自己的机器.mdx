最早让我认真想「本地跑模型」这件事的，是 GraphMap。

GraphMap 是我做的一个离线知识图谱 + RAG 系统。

它的卖点就四个字：断网可用。

目标服务器常常是没外网的——工厂内网、客户机房，或者干脆就是一台搬过去插上电就用的机器。

这种环境里，你调不了任何云端大模型 API。

没有网络，「把文档喂给 GPT」这条路直接被堵死。

那答案只能是：模型也一起搬过去，在自己机器上跑。

这就是本地部署（也叫私有化部署）最硬的理由——不是图便宜，是没得选。

当然，等真做起来你会发现，理由远不止「断网」这一个。

隐私是第一道。

文档里有客户数据、有内部结构、有不能出门的东西。

把这些塞给第三方 API，等于把家底交出去托管。

很多场景里，这一条就足够把云 API 否掉了。

成本算第二道。

云端按 token 计费，量一大账单就不好看。

尤其是 RAG 这种「每次检索先 embedding 一遍、再生成一遍」的活，调用频次高得吓人。

把模型买断式地跑在自己显卡或 CPU 上，边际成本趋近于零。

可控是第三道。

模型版本、上下文长度、停止词、并发数，全自己说了算。

不用看服务商的脸色，也不用担心它哪天降价又涨价，或者突然下线某个模型。

（DeepSeek 10 月那次大故障还热乎着——云上的东西，真挂起来你一点办法没有。）

所以从「把模型搬回自己的机器」，对我已经从尝鲜变成了刚需。

但紧接着第二个问题来了：

一个模型，到底是怎么「跑起来」的？

我以前用 API，只看到一个 endpoint，发一段话回去一段字。

黑盒。

本地部署逼着我把这层黑盒撕开。

先说最朴素的一句：所谓「跑模型」，本质就是在一台机器上加载一堆参数（几十亿到几千亿个浮点数），然后拿你的输入去算一遍，吐出下一个字。

GraphMap 里其实同时在用模型干两件不同的事：

一件叫 embedding（向量化），把文档和提问变成一串数字，好让向量数据库（pgvector）去比「谁和谁像」。

一件叫 generation（生成），才是我们常说的「聊天、写答案」。

前者不说话，后者说话。

前者默默把世界压成坐标，后者负责把坐标再翻回人话。

RAG 的精髓，就是先拿 embedding 把相关资料找出来，再拿 generation 照着资料开口。

（所以 GraphMap 的 Ollama 里挂了两个模型：nomic-embed-text 管 embedding，qwen3:8b 管 generation。）

到这里，动机和全景都有了。

下一期我们真的动手：用 Ollama 把这俩模型在 Docker 里跑起来，顺带把「量化」「GGUF」这些词拆开讲。

再往后，是从单机到三节点高可用（上海服务器上那套 Ollama-HA）——请求怎么在节点间流转、怎么流式吐字，这就是 event loop 的用武之地。

最后上 GPU，聊聊 MoE 和 SGLang：为什么 Qwen3.6-35B-A3B 这种「35B 参数却只激活 3B」的模型，能在一张卡上跑得动。

这条线，是从一个离线 RAG 项目，一步步滚出来的。

我也只是个边做边学的普通开发者，下面的内容难免有错漏，权当一份上手笔记。
